Build a complete, production-quality Gym Management mobile application called GymOS.

IMPORTANT: Do not build a simple UI mockup. Build a functional application with real navigation, persistent data, forms, validation, business logic, and a clean architecture.

PROJECT GOAL

GymOS is a complete management application for a gym owner who also works as the receptionist.

The owner/receptionist has full authority over the entire system.

The application should help manage:

- Members
- Membership plans
- Membership renewals
- Payments
- Attendance
- Trainers
- Reports
- Notifications
- Audit history
- Future biometric/fingerprint integration

The app should be designed primarily for Android mobile use but should have a responsive, modern, premium interface.

---

TECHNOLOGY

Use the best stack supported by Replit for building a modern mobile application.

Preferred architecture:

- React Native with Expo if fully supported
- TypeScript
- Clean component architecture
- Modern state management
- PostgreSQL database if backend/database is available
- Secure authentication
- REST API or appropriate backend architecture
- Modular code structure

If a native mobile application cannot be reliably built in the current Replit environment, build a high-quality responsive mobile-first application/PWA with architecture that can later be migrated to React Native.

Do not use unnecessary complexity.

IMPORTANT BUSINESS LOGIC

Membership Status

Possible statuses:

- Active
- Expiring Soon
- Expired
- Archived

Payment Status

Version 1:

- Completed
- Deleted/Void

No:

- Partial
- Pending installment
- Refund

Member Deletion

Archive rather than permanently delete.

Payment Deletion

Soft-delete/void the payment and preserve audit history.

Manual Extension

Always record:

- Previous expiry
- New expiry
- Reason
- Date/time
